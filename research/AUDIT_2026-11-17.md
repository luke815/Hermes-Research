# Audit, 2026-11-17

An outside review of the code, the research record and the dashboard, done from the GitHub copy of this repo. The modules that live only on the Hermes box (`regime_tester/costs.py`, `events.py`, `periods.py`, `episodes.py`, `scripts/intraday_store.py`, `env_token.py`, `http_get.py`) and the gitignored `data/raw/` were not available, so anything that depends on them is marked unverified.

Findings marked **verified** were checked line by line against the code or the data during the review. The rest come from a read of the code and are flagged so the fix can confirm them first.

The dashboard-side fixes are in the same pull request as this file (see the end). The research-code fixes are queued as the A-block at the top of `research/backlog.md`.

## Summary

- **No signal has been admitted in three weeks.** The four-factor heat score on the dashboard failed its own three-period holdout (`log.md:484`). `MANDATE.md` and the dashboard note still said the hot zone holds out of sample. Both are corrected in this pull request.
- **Several bugs can create edge that is not there, or hide edge that is.** These include a lookahead test that cannot fail, a confirmation step that scores the same signal whatever cell it is given, a survivor-only alt universe, costs that cancel inside every spread, and candles stored newest-first.
- **The process has drifted.** The test counter undercounts by about ten times. The multiple-testing bar went down as more cells were tried. Closed neighbours were re-tried. BTC event cells were queued that cannot reach their own sample bar. The best leads were left unfollowed.

Until A1 to A4 are done, treat every sweep result as unverified, admitted or not.

## Critical

### C1. The derivatives lookahead test cannot fail. Verified.
`tests/test_derivatives_lookahead.py:12-22` builds the measures once, copies the output, multiplies the copy after day t by 1.5, then checks that the original at t equals itself. It never rebuilds the measures from perturbed inputs. It also needs `data/raw/`, which is not committed. Separately, `tests/test_derivatives.py:44` points `derivatives.RAW` at a temp folder and never restores it, so test order decides what the lookahead test reads.

**Fix.** Copy the raw files into a temp folder and perturb every input after t, using random noise rather than a constant scale. Rebuild every measure from the perturbed copy and assert that all values up to t are unchanged. Restore `RAW` in a fixture.

### C2. Cross-sectional confirmation always scores 14-day momentum at a 1-day horizon. Verified.
`regime_tester/confirm.py:169` calls:

    score_cross_section(panel, lambda close: close.pct_change(14), horizon=1)

whatever the cell id says. `scripts/confirm_daemon.py:30-34` puts cross-sectional cells first, so every recent confirmation is the same test under a different name. The dashboard's 30 latest confirmations all report validation t = −0.2472 on n = 549.

**Fix.** Build the measure, transform, threshold and target from the cell id, using the same code path as the sweep. Add a test asserting that two different cells give different validation statistics. Mark every cross-sectional confirmation recorded since the confirmation step existed as void.

### C3. The alt universe is survivors only. Verified.
- `scripts/build_universe_laevitas.py:40` builds the panel from `data/laevitas/instruments.json`, which lists what trades on 2026-11-16. FTTUSDT, SRMUSDT, MATICUSDT, EOSUSDT, OCEANUSDT, FTMUSDT and AGIXUSDT are not in it.
- `scripts/pull_listed_history.py` keeps only rows with `delisted == 0` before it pulls anything.
- The "delisted" flag only catches names that are still in the catalogue but stopped printing. L4 reports 0 confirmed delisted out of 5,185.

Every cross-sectional result is computed on coins that survived to today. That flatters momentum and the long side, and hides the short side's best trades.

**Fix.** Build a point-in-time universe from the exchange archives already on disk (`data/binance_span.csv`, `bybit_span.csv`, `okx_span.csv`, with 31, 309 and 154 stopped names), with a listed-from and listed-to date per name. Rank each date only among names listed on that date.

### C4. "Net of costs" is gross in every spread. Verified.
`scripts/sweep_xs.py:399` subtracts one flat round trip from every name's forward return. A decile spread is flagged minus rest, so the cost cancels. For `rel_*`, the same cost is also taken off BTC and cancels again. The same pattern appears in `score_xs_rs.py:109-110`, `score_xs_funding_oi.py:124-125` and `sweep.py:260-270`. Funding carry is never charged, even when funding is the signal.

**Fix.** Charge costs per traded leg, scaled by turnover, so a long-short spread pays both legs. Add funding carry, signed by side, from the per-name funding history. Report gross and net side by side.

### C5. `rel_*` targets equal `ret_*`, and `ratio_btc` is always empty. Verified on the data.
`sweep_xs.py:400` looks for a column named `"BTC"`, but panel columns are venue-prefixed (`binance_BTCUSDT`). The check is always false, so the relative return is scored against zero. `regime_tester/vectorized.py:176` does the same check, so `ratio_btc` is all NaN. The dashboard leaderboard shows every rel/ret pair with identical scores, while the sweep reports "duplicates: 0". Even with the column found, subtracting BTC's return cancels inside a same-day cross-sectional rank, so rel and ret cells are one test either way.

**Fix.** Drop the `rel_*` cross-sectional targets, or make them a residual against beta-times-BTC. Find BTC by base coin. Count the duplicates out of N.

### C6. Bybit and OKX candles are stored newest-first. Verified.
`scripts/pull_listed_history.py` writes the Bybit (`bybit_klines`) and OKX (`okx_klines`) bars in the order the API returns them, which is newest first, with no sort. `confirm.py:168` and `regime_tester/cross_section.py` do not sort either, so `pct_change`, `shift` and every rolling window run backwards in time on those names. (`scripts/cycle.py` now sorts its own input in this pull request.)

**Fix.** Sort by date and drop duplicate dates on write. Sort again on every read. Add a test that fails on a descending file.

### C7. The forecast ledger scores forecasts against the past. Verified.
`ledger.csv`'s `realized_10d` holds the trailing 10-day BTC return. Every row matches `btc[t] / btc[t-10] − 1`, including rows from the last 10 days that should still be empty. The page's "73% right, 22 of 30" compares each forecast with the move that had already happened. Scored against the next 10 days, 12 rows have matured, and they span 2 independent windows.

**Fix (done in this pull request).** `build_data_json.score_ledger` takes the forward return from the price series and leaves it null until the horizon has passed. The script that writes `ledger.csv` is not in the repo; find it and fix it at the source.

## High

**H1. The deflated bar uses the cell's own sample size as N.** Verified. `confirm_daemon.py:46` passes `family_n=cell["train_n"]`. The manual runs used "distinct combinations", which moved the trend bar from 4.11 to 3.26 for the same 16,848 cells. **Fix:** N is the number of validation attempts made in the family (109 so far), and it only goes up. Use Holm, or a deflated Sharpe ratio, on that N.

**H2. Plain t-stats on overlapping returns, labelled Newey-West.** Verified for `score.py:20-27` (24-bar forward returns, about √24 too large) and `confirm.py:177` (a plain t written to `t_newey_west`). Agent-reported for `regimemap.py:52-73` and `factors.py:86-95`. Early results quote n ≈ 240 for overlapping 10-day windows (`results/2026-10-27_*`). **Fix:** use non-overlapping samples or HAC errors with lag ≥ horizon. Report the independent n in every results file.

**H3. The heat score was selected in-sample, then called out-of-sample.** Verified. `heat.py:21-24` dropped three factors "on the full history through 2026-10-26", which includes the period later used as held out. The three-period test rejected the four that remained (`log.md:484`). The rolling fit gives three of four a negative weight. **Fix:** relabel the heat score as context (done on the page and in `MANDATE.md`). Retest it only under a fresh pre-registration with a period it has never seen.

**H4. One coin is counted many times.** Agent-reported. The Laevitas panel holds about 5,056 instruments on 13 venues, 24 of them BTC, including coin-margined and USDC perps. They are ranked as separate names (`sweep_xs.py:62-67`), which inflates breadth and adds stale prices from thin venues. **Fix:** one row per base coin from the most liquid venue (the `base_of` helper in `score_xs_rs.py` already exists), with a liquidity floor.

**H5. Partial bars and funding.** Verified.
- The Binance, Bybit and OKX kline calls return today's unfinished bar, and `append_panel_xs.py:56` never replaces it.
- Funding keeps the last print of each day (`by_day[day] = rate`), not the day's sum, across 1h, 4h and 8h venues.
- Bybit funding is capped at 200 prints and OKX has none.

**Fix:**
- Drop any bar whose close time is in the future.
- Store funding as the daily sum, plus the interval.
- Paginate funding history.

**H6. The live board is stale but carried a fresh stamp.** Verified. `live_daemon.board()` reads the 1-hour store, and nothing in this loop updates it. The board in `live.json` is from 2026-11-05 under a current `as_of`. **Fix (partly in this pull request):** `health.rs_stale` and `rs_age_sec` are now written and the page shows the board's own age. Still open: restore whatever used to fill `data/intraday/` hourly.

**H7. The live book marks closed legs.** Verified on the data. `book_live` reads `signals/book.csv`, which still holds the 1000PEPE and AIN longs that `data.json`'s book shows closed on 2026-11-12. The live paper return (−41%) is the mark of positions that no longer exist. **Fix:** write closes to `signals/book.csv`, or filter it by the book's open legs. The page now ignores live marks when the book has no open leg.

**H8. The scheduler ran missing scripts and recorded them as run.** Verified. `rank_universe.py` and `book_composite.py` do not exist. **Fix (in this pull request):** the rerank slot runs `universe_rank.py`, book marks are off until `book_composite.py` exists, and missing, failed and timed-out jobs reach the health post.

**H9. Unverified, from the code read:**
- `sweep_daemon.py:101-104` rebuilds the leaderboard from the newest `*.csv`, which can be an `_xs` file.
- `sweep_xs._fast_rank_pct` requires a full 252-bar window where the reference loop allows a partial one, so the vectorized and reference results differ before bar 252.
- `confirm.py` has no embargo between validation and test.

## Medium

These are agent-reported unless marked otherwise.

- `vectorized.py:292-298` cuts `ratio_btc`, `acceleration`, `persistence` and `divergence_20` at raw ≥80 or ≤20. On 0/1 or ratio scales that flags everything or nothing.
- `sweep.py:191-201` runs Newey-West on a gap series with the NaNs dropped, so lags span calendar gaps. Pooled cells average per-token t-stats and sum n across correlated majors.
- `derivatives.py:177,192,202` uses row-count windows (`diff(7)`, `rolling(7)`) on gappy series. `daily()` keeps the last row in file order, not the latest timestamp.
- `panel.py:62` weights missing alt funding as zero.
- `refresh_coinalyze.py:64,83` uses one maximum timestamp across symbols, so a symbol that falls behind never backfills. Its write is not atomic.
- `daemon_base.py:50` uses relative lock paths, and `max_cycle_sec` only logs.
- `supervisor.sh` and `supervisor.py` write different formats to the same heartbeat file.
- `indicators.py:266` silently falls back to a daily band for `weekly_band`.
- `vectorized.py:54` funding carry is off by one day. The function is unused.
- 1.3 million options cells and 1.0 million derivatives cells were enumerated (S8) but never scored. `sweep.py:239` does not build them.

## Process

1. **The test-budget counter undercounts.** "53 tests since the last admission" covered 242 confirmation attempts plus 444 C2 to C7 and cross-sectional cells. Most were exempted as "not a confirmation attempt". The costs table, which is plumbing, reset the counter. Count every scored cell that could have been admitted.
2. **The bar went down as the search grew.** See H1. With 3.8 million enumerated cells, 2 + 0.5·log10(N) is about 5.3.
3. **Closed neighbours were re-tried** despite `RESEARCH_SWEEP.md:38`. Examples: sma_200 (ret_10, ret_1, chg_30, chg_3, the 90th percentile), keltner_width, weekly_band, stc, ema_50, atr_14 and tsi.
4. **Pre-registration drift.**
   - The C3 to C7 hit definition was changed after the first scoring (`log.md:839`).
   - The 10-19 to 10-26 block is reconstructed with no pre-registration, yet it closes whole families.
   - Pre-registrations and verdicts are committed together, which proves nothing about order. Commit the pre-registration before scoring.
5. **Tests that cannot pass.** BTC has 22 bottom and 14 top episodes in total against a 30-episode bar. The generator still promises "about 30 to 50". Stop queueing single-asset BTC event cells. Pool across names with date-clustered errors instead.
6. **Missing evidence.** 58 of the 153 results files cited in `research/*.md` are not in this repo. That breaks the rule that no number appears without a results file.
7. **Effort.**
   - Nov 12 to 15 went to Bybit raw-trade slices for memecoins that fail the $20M open-interest floor anyway. They left 27 `bybit_prices_*`, 24 `push_*` and 32 `append_*` one-off scripts.
   - `ops/hourly.log` stopped on 2026-10-29.
   - The confirmation daemon has been idle since 2026-11-13.

## Where the edge is more likely

In order. None of these is a claim of edge; each is a test worth pre-registering once A1 to A4 hold.

1. **Cross-sectional short-horizon reversal.** Relative strength predicted next-day returns negatively in all three periods, at all six lookbacks. For the 14-day lookback, the information coefficient (IC) was:

   | Period | IC | t |
   |---|---|---|
   | Train | −0.032 | −4.55 |
   | Validation | −0.016 | −1.86 |
   | Test | −0.010 | −1.16 |

   (`results/2026-11-16_xs_relative_strength.json`.) It is decaying, and costs at a 1-day horizon may take it all. Test 1-day and 3-day horizons with a liquidity floor, one row per coin, per-leg costs and carry, and volatility-scaled weights, on the point-in-time universe.
2. **The derivatives family on BTC and ETH at 1 to 3 days, and as a regime filter for the alt cross-section.** Candidates are skew, risk reversal, implied minus realized vol, basis, funding and open-interest change. Daily horizons give hundreds of independent observations, where top and bottom events give about 20.
3. **Crowding before alt tops.** Open interest to volume above its 90th percentile, and 30-day OI change, showed lift above 1 in train and validation on ADA, SOL, LINK, XRP and AVAX (`results/2026-11-15_c2_rerun.json`). Score it as a pooled panel with errors clustered by date, not as an episode count.
4. **Funding extremes in the cross-section.** Crowded longs (top-decile funding) against forward returns, with carry charged. This is the cleanest economic story in the data on disk.
5. **Liquidation cascades.** Laevitas has history from 2021-11, and no per-name cascade test exists.

Stop: single-asset BTC top and bottom cells, memecoin backfills, and confirmations until C2 is fixed.
